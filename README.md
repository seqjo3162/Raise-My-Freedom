# Raise-My-Freedom

Обход блокировок, которые вбрасывает провайдер. Не VPN и не прокси-сервис: локальная
перехватка DNS-запросов и TLS-рукопожатий, после которой приложение даже не замечает,
что что-то было.

Ядро и модули написаны на C, собираются обычным `make`, веб-интерфейс — отдельный
бинарник на той же странице.

Идея и базовые приёмы — из [zapret](https://github.com/bol-van/zapret) (он же форк
nfqws). Здесь всё переделано в модульную систему: каждый сервис — отдельный плагин,
а общий обход лежит в `src/common/site_bypass.c` и переиспользуется.

## Что проверено, а что нет

Честно, чтобы не было сюрпризов:

- **Собирается** без ошибок. Проверено на Pop!_OS 24.04, gcc 13.3, на чистом клоне
  с нуля. Других систем не проверял.
- **Живой проверки обхода не было.** Я диагностировал подмену DNS на GitHub —
  сравнил UDP-DNS с DoH и убедился, что адрес из DoH отдаёт рабочее соединение,
  а из UDP — мёртвый. Но сам модуль `github` я только собрал и загрузил:
  `plug_inject()` правит iptables, для этого нужен root, и я его не запускал.
- **Ни один модуль не проверен на живом трафике.** Ни Discord, ни Telegram, ни
  остальные десять шаблонных. Код у них общий, но каждый сервис по отдельности
  я не гонял. Первый запуск стоит делать аккуратно, с `logs/` и снапшотом
  правил в руке.
- **Telegram.** Собственная реализация: MTProxy на `127.0.0.1:1443` с нативным
  WebSocket-транспортом и FakeTLS, с откатом на TCP к ДЦ. Модуль собирается чисто,
  предупреждений нет. Но **реальный клиент не подключался** — в моей среде внешние
  адреса Telegram недоступны, так что авторизация не проверена. Галочка «WebSocket»
  в вебе включает его по умолчанию; выключи, если клиент не заходит.
- **Только Linux.** Требуется root, потому что правила ставятся в iptables. Без root
  модуль запускается частично: DNS-перехват не работает, остаётся только релей.
- **Не умеет всё.** Закрывает DNS-hijack и SNI-фильтрацию. Если блокировка сделана
  иначе — по IP, по TLS fingerprint, через DPI на уровне приложения — не поможет.

## Установка

Нужен root и примерно минута на сборку.

```bash
git clone https://github.com/seqjo3162/Raise-My-Freedom.git
cd Raise-My-Freedom
sudo ./scripts/install-bypass.sh
```

Скрипт соберёт всё, поднимет веб на `127.0.0.1:8080` и запустит четыре плагина:
`vrchat`, `google`, `x`, `speedtestbyookla`. Остальные включаются в вебе.

**Что он делает с системой** — знай, что соглашаешься:

- переключает DNS интерфейса на `127.0.0.1` (`resolvectl dns`);
- добавляет цепочки в таблицу `nat` и вешает их на `OUTPUT`;
- убивает уже запущенные `rmf` и `rmf-web`.

Откатить всё:

```bash
sudo ./scripts/cleanup.sh
```

Он снимает только цепочки этого проекта, чужие правила не трогает, а перед удалением
сохраняет снапшот в `logs/iptables-before-cleanup.rules`. Если хочешь вернуть DNS
вручную:

```bash
sudo resolvectl dns enp42s0 8.8.8.8 1.1.1.1
```

## Пользоваться

Веб: **http://127.0.0.1:8080** — там галочки плагинов, логи и настройки Telegram.

Из консоли:

```bash
sudo build/bin/rmf list                    # что собрано
sudo build/bin/rmf inject --discord        # включить обход для одного сервиса
```

`inject` работает, пока живёт процесс: он держит форвардер и релей, убьёшь — правила
снимутся при выходе. Постоянно — через веб или свой unit.

### Скрипты

```bash
sudo ./scripts/install-bypass.sh   # установка: сборка, веб, четыре плагина
sudo ./scripts/cleanup.sh          # снять наши правила, снапшот в logs/
sudo ./scripts/start-rmf.sh        # один плагин в консоли, по умолчанию discord
./scripts/test_bypass.sh           # замерить скорость через обход
```

Веб можно поднять на другом порту: `RMF_PORT=18080 ./build/bin/rmf-web`.
Корень проекта он берёт из `RMF_ROOT`, а если её нет — из расположения бинарника.

## Если не заработало

Самое частое, по порядку:

**Домен резолвится в мусорный IP.** Проверь, подменяет ли провайдер DNS:

```bash
dig +short github.com                    # системный
curl -sH "accept: application/dns-json" \
  "https://1.1.1.1/dns-query?name=github.com&type=A"   # DoH
```

Если ответы разные — это подмена, и модуль должен её обходить. Если после старта
модуля всё ещё мусор — сбрось кеш резолвера: `sudo resolvectl flush-caches`.

**Порт занят.** Веб сидит на 8080. Проверь: `ss -tlnp | grep 8080`. Занят — поменяй
через переменную окружения `RMF_PORT` при запуске.

**Правила не применились.** `sudo iptables -t nat -S | grep -i bypass` покажет, что
поставилось. Пусто — не хватило root, в логе модуля будет ошибка.

**Запустил, а ничего не поменялось.** Проверь, что браузер не ходит через свой DoH:
Chrome и Firefox умеют шифровать DNS сами, и тогда подмены уже нет — проблема в
другом месте. И проверь, что включён именно тот плагин, который нужен, в вебе.

**Откат не помог.** Правила могли остаться от прошлой установки. Сравни снимок:
`sudo iptables-restore < logs/iptables-before-cleanup.rules`.

## Что внутри

17 модулей. Десять из них — тонкая декларация поверх общего `site_bypass`: список
доменов, цепочка, порты, всё. Логика одна и та же, добавление нового сервиса занимает
двадцать строк (см. ниже).

Шаблонные, общий обход: `activision`, `battlenet`, `electronicarts`, `epicgames`,
`github`, `roblox`, `soundcloud`, `spotify`, `steam`, `twitch`.

Собственная реализация: `discord`, `telegram` (MTProxy + WebSocket), `x`, `google`, `vrchat`,
`speedtestbyookla`, `cloudflaredns`.

`github` — показательный случай. Провайдер подменяет A-записи GitHub, отдавая
адреса из `140.82.121.0/24`, куда TCP не доходит. `site_bypass` резолвит через DoH
первым делом, поэтому подменённый ответ не доходит до приложения вообще.

`discord` сделан иначе: там ещё и IP pinning — 16 доменов закреплены за конкретными
адресами Cloudflare, чтобы провайдерский DNS не подсунул своё.

## Как добавить свой сервис

Скопируй любой шаблонный модуль и замени три вещи: список доменов, цепочку, порты.

```c
static const char *const site_domains[] = { "mysite.com", NULL };

#define SITE_MODULE_PREFIX   mysite
#define SITE_MODULE_CONFIG   mysite_config_t
#define SITE_MODULE_CTX      mysite_ctx_t
#define SITE_MODULE_CHAIN    MYSITE_BYPASS
#define SITE_DNS_PORT        18580
#define SITE_RELAY_PORT      18480
#define SITE_MARK            0x4d5a
#define SITE_LABEL           "MYSITE"
#include "src/common/site_module_impl.h"
```

Порты не должны совпадать с уже занятыми: DNS `18556, 18558, 18562–18568, 18590`,
релей `18456, 18458, 18462–18468, 18490`, плюс `18443–18447` у discord, google, x,
speedtestbyookla и vrchat.
Метка — **обязательно** в диапазоне `0x4d50`–`0x4d5f`: правило `-m mark --mark
0x4d50/0xfff0 -j RETURN` в цепочке не даёт трафику релея завернуться сам в себя.
У существующих модулей метки стоят в `0x4d66`–`0x4d72`, то есть вне этого диапазона —
на живой трафике я это не проверял, но выглядит как ошибка.

Дальше две строки в `Makefile` — в `MODULES` и вызов `PLUGIN_template` — и `make plugs`.

Подробности API: `src/common/site_bypass.h`, `src/plugin_api.h`.

## Как это устроено

Коротко, без разбора исходников.

Ядро ловит DNS-запрос и смотрит на имя домена. Если оно в списке модуля — запрос
не уходит провайдеру, а попадает в локальный форвардер, который резолвит через DoH.
Дальше соединение на 443 заворачивается на локальный релей: он читает ClientHello,
режет TLS-запись и пересылает остаток. Провайдерский DPI не видит целого SNI и теряет
сигнатуру.

Цепочки в iptables именуются `<СЕРВИС>_BYPASS`, метки на пакетах — `0x4d..`. Всё это
снимает `scripts/cleanup.sh`.

HTTP API веба, если нужно дёргать из своего кода: `GET /api/status`,
`/api/start?plugin=`, `/api/stop?plugin=`, `/api/stopall`, `/api/logs`.
Полный список — в `webui/server.c`.
