# Raise-My-Freedom

Обход блокировок, которые вбрасывает провайдер. Не VPN и не прокси-сервис: локальная
перехватка DNS-запросов и TLS-рукопожатий, после которой приложение даже не замечает,
что что-то было.

Ядро и модули написаны на C, собираются обычным `make`, веб-интерфейс — отдельный
бинарник на той же странице.

Идея и базовые приёмы — из [zapret](https://github.com/bol-van/zapret) (он же форк
nfqws). Здесь всё переделано в модульную систему: каждый сервис — отдельный плагин,
а общий обход лежит в `src/common/site_bypass.c` и переиспользуется.

## Что проверено, а что нет

Честно, чтобы не было сюрпризов. Собирается на Pop!_OS 24.04 LTS, gcc 13.3.

**Проверено на живой трафике** — в рабочей копии, из которой этот репозиторий
взялся. Код модулей оттуда и здесь один, но именно эту сборку я не запускал:
всё ниже проверялось до переноса.

Активны были `vrchat`, `google`, `github` (плюс `hf`, которого в этом репозитории
нет). Из них проверено, запрос с браузерным User-Agent, по две попытки:

| Модуль | Результат |
|---|---|
| `github` | `github.com` → `200` |
| `google` | `google.com/generate_204` → `204`, `youtube.com` → `200` |
| `vrchat` | `docs.vrchat.com` → `200`, `api.vrchat.cloud` → `404` (ответ сервера) |

Проверено раньше, в той же копии, но на сборке без слоя `netfilter` — код модулей
с тех пор менялся, так что перепроверяй первым делом:

`spotify` → `open.spotify.com` `200` (163 КБ), `api.spotify.com` `301` ·
`steam` → `200` · `twitch` → `200` · `roblox` → `200` · `activision` → `200` ·
`battlenet` → `302` · `cloudflaredns` → `301` · `epicgames` → `404`.

Коды `3xx` и `4xx` здесь — ответ самого сайта, а не отказ модуля.

**Не проверено на живом трафике:** `discord`, `telegram`, `x`, `soundcloud`,
`speedtestbyookla`, `electronicarts`. Собраны, символы на месте, но каждый сервис
по отдельности я не гонял. Первый запуск — со снапшотом правил в руке.

**Telegram.** Собственная реализация: MTProxy на `127.0.0.1:1443` с нативным
WebSocket-транспортом и FakeTLS, с откатом на TCP к ДЦ. Собирается чисто.
**Реальный клиент не подключался** — в моей среде внешние адреса Telegram
недоступны, так что авторизация не проверена. Галочка «WebSocket» в вебе включает
его по умолчанию; выключи, если клиент не заходит.

**YouTube.** Страница и видеозапросы работают. `youtubei.googleapis.com` (player API)
остаётся недоступен — набор параметров, которыми играет плеер, велик, и подбирать
его вслепую дорого. На просмотр видео это не влияет.

**Только Linux.** Нужен root: правила ставятся в iptables. Без root модуль
запускается частично — DNS-перехват не работает, остаётся только релей.

**Не умеет всё.** Закрывает DNS-hijack и SNI-фильтрацию. Если блокировка сделана
иначе — по IP, по TLS fingerprint, через DPI на уровне приложения — не поможет.

достаточно было его одного. В этом репозитории `universal` нет, так что если

## Установка

Нужен root и примерно минута на сборку.

```bash
git clone https://github.com/seqjo3162/Raise-My-Freedom.git
cd Raise-My-Freedom
sudo ./scripts/install-bypass.sh
```

Скрипт — тонкая обёртка над `run.sh`. Соберёт всё, поднимет веб на
`127.0.0.1:8080` и запустит три плагина: `vrchat`, `google`, `github`. Остальные
включаются в вебе или так:

```bash
sudo ./run.sh start google github vrchat spotify
```

Свой набор по умолчанию задаётся одной строкой в `run.sh`:
`DEFAULT_PLUGINS=(vrchat google github)`. Больше трёх-четырёх без проверки не
включай — см. ограничение выше.

**Что он делает с системой** — знай, что соглашаешься:

- переключает DNS интерфейса на `127.0.0.1` (`resolvectl dns`);
- добавляет цепочки в таблицу `nat` и вешает их на `OUTPUT`;
- убивает уже запущенные `rmf` и `rmf-web`.

Откатить всё:

```bash
sudo ./scripts/cleanup.sh
```

Он снимает только цепочки этого проекта, чужие правила не трогает, а перед удалением
сохраняет снапшот в `logs/iptables-before-cleanup.rules`. Если хочешь вернуть DNS
вручную:

```bash
sudo resolvectl dns enp42s0 8.8.8.8 1.1.1.1
```

## Пользоваться

Веб: **http://127.0.0.1:8080** — там галочки плагинов, логи и настройки Telegram.

Из консоли:

```bash
sudo build/bin/rmf list                    # что собрано
sudo build/bin/rmf inject --discord        # включить обход для одного сервиса
sudo ./run.sh start github spotify         # несколько плагинов сразу
sudo ./run.sh stop                         # снять всё
sudo ./run.sh save                         # снимок состояния в cache/save/
sudo ./run.sh restore                      # вернуться к снимку
```

`run.sh restart` и кнопка «Перезапуск» в вебе делают полный цикл: снять всё,
пересобрать, поднять заново. **Часто так делать не стоит** — при смене набора
IP VRChat может счесть это подозрительным. Для точечной работы есть старт и стоп
отдельного плагина.

`inject` работает, пока живёт процесс: он держит форвардер и релей, убьёшь — правила
снимутся при выходе. Постоянно — через веб или свой unit.

### Скрипты

```bash
sudo ./scripts/install-bypass.sh   # установка: сборка, веб, три плагина
sudo ./scripts/cleanup.sh          # снять наши правила, снапшот в logs/
sudo ./scripts/start-rmf.sh        # один плагин в консоли, по умолчанию github
./scripts/doctor-all.sh            # прогнать доктора по всем модулям
./scripts/test_bypass.sh           # замерить скорость через обход
```

Веб можно поднять на другом порту: `RMF_PORT=18080 ./build/bin/rmf-web`.
Корень проекта он берёт из `RMF_ROOT`, а если её нет — из расположения бинарника.

## Если не заработало

Самое частое, по порядку:

**Домен резолвится в мусорный IP.** Проверь, подменяет ли провайдер DNS:

```bash
dig +short github.com                    # системный
curl -sH "accept: application/dns-json" \
  "https://1.1.1.1/dns-query?name=github.com&type=A"   # DoH
```

Если ответы разные — это подмена, и модуль должен её обходить. Если после старта
модуля всё ещё мусор — сбрось кеш резолвера: `sudo resolvectl flush-caches`.

**Порт занят.** Веб сидит на 8080. Проверь: `ss -tlnp | grep 8080`. Занят — поменяй
через переменную окружения `RMF_PORT` при запуске.

**Правила не применились.** `sudo iptables -t nat -S | grep -i bypass` покажет, что
поставилось. Пусто — не хватило root, в логе модуля будет ошибка.

**Запустил, а ничего не поменялось.** Проверь, что браузер не ходит через свой DoH:
Chrome и Firefox умеют шифровать DNS сами, и тогда подмены уже нет — проблема в
другом месте. И проверь, что включён именно тот плагин, который нужен, в вебе.

**Откат не помог.** Правила могли остаться от прошлой установки. Сравни снимок:
`sudo iptables-restore < logs/iptables-before-cleanup.rules`.

## Что внутри

17 модулей. Десять из них — тонкая декларация поверх общего `site_bypass`: список
доменов, цепочка, порты, всё. Логика одна и та же, добавление нового сервиса занимает
двадцать строк (см. ниже).

Шаблонные, общий обход: `activision`, `battlenet`, `electronicarts`, `epicgames`,
`github`, `roblox`, `soundcloud`, `spotify`, `steam`, `twitch`.

Собственная реализация: `discord`, `telegram` (MTProxy + WebSocket), `x`, `google`,
`vrchat`, `speedtestbyookla`, `cloudflaredns`.

Общий обход — не один файл, а три слоя:

- `src/common/site_bypass.c` — что делать: перехват DNS по имени, закреплённые
  адреса, релей, доктор, стабильные пины;
- `src/common/plain_relay.c` — рель без модификации TLS, для модулей, которым нужно
  просто завернуть 443 на свой порт;
- `src/netfilter/` — платформенный слой. **Весь iptables и `SO_MARK` лежат только
  здесь**, в `netfilter_linux.c`. Выбор платформы делает `Makefile`: в сборку
  попадает ровно один бэкенд, `netfilter_linux.c` или `netfilter_win.c`. Код нигде
  не спрашивает «какая у меня ОС» — это решение принимается при сборке.

`github` — показательный случай. Провайдер подменяет A-записи GitHub, отдавая
адреса из `140.82.121.0/24`, куда TCP не доходит. `site_bypass` резолвит через DoH
первым делом, поэтому подменённый ответ не доходит до приложения вообще.

`discord` сделан иначе: там ещё и IP pinning — 16 доменов закреплены за конкретными
адресами Cloudflare, чтобы провайдерский DNS не подсунул своё.

## Как добавить свой сервис

Скопируй любой шаблонный модуль и замени три вещи: список доменов, цепочку, порты.

```c
static const char *const site_domains[] = { "mysite.com", NULL };

#define SITE_MODULE_PREFIX   mysite
#define SITE_MODULE_CONFIG   mysite_config_t
#define SITE_MODULE_CTX      mysite_ctx_t
#define SITE_MODULE_CHAIN    MYSITE_BYPASS
#define SITE_DNS_PORT        18580
#define SITE_RELAY_PORT      18480
#define SITE_MARK            0x4d5a
#define SITE_LABEL           "MYSITE"
#include "src/common/site_module_impl.h"
```

Порты не должны совпадать с уже занятыми. Занятые DNS-порты:
`18556, 18558, 18562–18568, 18590`; релей — `18445` у google, `18444` у discord,
`18444` и `15353` у vrchat, `1443` у telegram.

**Про метки — честно.** Правило исключения собственного трафика одно на проект:
`-m mark --mark 0x4d50/0xfff0 -j RETURN`, то есть пропускает пакеты с меткой
`0x4d50`–`0x4d5f`. У большинства существующих модулей метки стоят выше — в
`0x4d66`–`0x4d72`, то есть **вне** этого диапазона. На живом трафике это не
проявляется, и вот почему: рель подключается к адресу CDN, а правила модуля
нацелены на закреплённые адреса того же CDN, поэтому пакеты реле в собственные
правила не попадают. Метка — страховка на случай, если адреса совпадут. Новому
модулю лучше брать `0x4d50`–`0x4d5f`; если тянет на свои — знай, что страховка
на него не распространяется.

Дальше две строки в `Makefile` — в `MODULES` и вызов `PLUGIN_template` — и `make plugs`.

Подробности API: `src/common/site_bypass.h`, `src/plugin_api.h`.

## Как это устроено

Коротко, без разбора исходников.

Ядро ловит DNS-запрос и смотрит на имя домена. Если оно в списке модуля — запрос
не уходит провайдеру, а попадает в локальный форвардер, который резолвит через DoH.
Дальше соединение на 443 заворачивается на локальный релей: он читает ClientHello,
режет TLS-запись и пересылает остаток. Провайдерский DPI не видит целого SNI и теряет
сигнатуру.

Цепочки в iptables именуются `<СЕРВИС>_BYPASS`, метки на пакетах — `0x4d..`. Созданные
цепочки слой `netfilter` записывает в реестр `/run/rmf/chains`, поэтому очистка
знает, что снимать, даже если процесс был перезапущен. Файл можно удалять — он
пересоздастся. Всё это снимает `scripts/cleanup.sh` или веб (`POST /api/flush`).

Собственный трафик обхода отмечен через `SO_MARK`, чтобы не попасть в собственные
же правила. На Linux это маркировка пакетов; в заготовке Windows-бэкенда на его
месте фильтрация по PID — на Windows `SO_MARK` не существует, и PID точнее.

HTTP API веба, если нужно дёргать из своего кода: `GET /api/status`,
`/api/start?plugin=`, `/api/stop?plugin=`, `/api/stopall`, `/api/logs`,
`/api/rebuild`, `/api/save`, `/api/flush`, `/api/restart?target=web|proxy|all`.
Полный список — в `GET /api/info` и в `webui/server.c`.
