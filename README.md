# Raise-My-Freedom

Обход блокировок, которые вбрасывает провайдер. Не VPN и не прокси-сервис: локальная
перехватка DNS-запросов и TLS-рукопожатий, после которой приложение даже не замечает,
что что-то было.

Ядро и модули написаны на C, собираются обычным `make`, веб-интерфейс — отдельный
бинарник на той же странице.

Идея и базовые приёмы — из [zapret](https://github.com/bol-van/zapret) (он же форк
nfqws). Здесь всё переделано в модульную систему: каждый сервис — отдельный плагин,
а общий обход лежит в `src/common/site_bypass.c` и переиспользуется.

---

## Что работает, а что нет

- **Работает.** Обход подмены DNS и SNI-фильтрации. Проверено на живом трафике
  на Pop!_OS 24.04: `github`, `google`, `youtube`, `spotify`, `steam`, `twitch`,
  `roblox`, `activision`, `vrchat`, `battlenet`, `epicgames`, `cloudflaredns`
  отдают живые ответы.
- **Не проверено на живом трафике:** `discord`, `telegram`, `x`, `soundcloud`,
  `speedtestbyookla`, `electronicarts`. Собраны, но каждый по отдельности я не
  гонял. Начинай с них осторожно, со снапшотом правил в руке.
- **YouTube.** Видео смотрится, но player API (`youtubei.googleapis.com`)
  недоступен. На просмотр не влияет.
- **Telegram.** Авторизация не проверена: внешние адреса Telegram в моей среде
  недоступны. Галочка «WebSocket» в вебе включает его по умолчанию — выключи,
  если клиент не заходит.
- **Только Linux, нужен root.** Правила ставятся в iptables. Без root модуль
  работает частично: DNS-перехват не работает, остаётся рель.
- **Не умеет блокировки по IP, по TLS fingerprint и на уровне приложения.**

## Установка

```bash
git clone https://github.com/seqjo3162/Raise-My-Freedom.git
cd Raise-My-Freedom
sudo ./scripts/install-bypass.sh
```

Дальше скрипт всё сделает сам: соберёт проект, поднимет веб и включит три
модуля — `vrchat`, `google`, `github`. Больше ничего вводить не надо.

Потом открой в браузере **http://127.0.0.1:8080** и вкл/выкл 
только то что тебе требуются в данный момент.

**Откатить всё:**

```bash
sudo ./run.sh stop          # снимает правила, останавливает процессы, возвращает DNS
sudo ./scripts/cleanup.sh   # очистка iptables 
```

`run.sh stop` возвращает DNS на `8.8.8.8` и `1.1.1.1`. Чужие правила не
трогаются, но на всякий случай `cleanup.sh` перед удалением сохраняет снимок в
`logs/iptables-before-cleanup.rules`.

Если веб по какой-то причине не запустился/не работает, 
модули можно включать из папки проекта:

```bash
sudo ./run.sh start spotify steam
```

## Полезно знать:

- **«Перезапуск» в web**
  Cнимает правила, билдит проект,
  поднимает заново. Не жми часто перезапуск во время
  игры у которых EAC. Они могут начать жаловаться на манипуляции с
  игрой или трафиком игры, например: VRChat.
- **Снимок состояния**
  `run.sh save` в консоли или кнопка в вебе, перед
  экспериментами, а `run.sh restore` вернёт как было.

Консольные команды, если веб недоступен:

```bash
sudo ./run.sh start spotify steam   # включить модули при старте
sudo ./run.sh stop                  # снять всё
sudo ./run.sh save                  # снимок в cache/save/
sudo ./run.sh restore               # вернуться к снимку
```

Вспомогательное:

```bash
sudo ./scripts/doctor-all.sh   # проверить, что перехват вообще работает
./scripts/test_bypass.sh       # замерить скорость через обход
```

## Если не заработало

Самое частое, по порядку:

**Домен резолвится в мусорный IP.** Проверь, подменяет ли провайдер DNS:

```bash
dig +short github.com                    # системный
curl -sH "accept: application/dns-json" \
  "https://1.1.1.1/dns-query?name=github.com&type=A"   # DoH
```

Если ответы разные — это подмена, и модуль должен её обходить. Если после старта
модуля всё ещё мусор — сбрось кеш резолвера: `sudo resolvectl flush-caches`.

**Порт занят.** Веб сидит на 8080. Проверь: `ss -tlnp | grep 8080`. Занят — поменяй
через переменную окружения `RMF_PORT` при запуске.

**Правила не применились.** `sudo iptables -t nat -S | grep -i bypass` покажет, что
поставилось. Пусто — не хватило root, в логе модуля будет ошибка.

**Запустил, а ничего не поменялось.** Проверь, что браузер не ходит через свой DoH:
Chrome и Firefox умеют шифровать DNS сами, и тогда подмены уже нет — проблема в
другом месте. И проверь, что включён именно тот плагин, который нужен, в вебе.

**Откат не помог.** Правила могли остаться от прошлой установки. Сравни снимок:
`sudo iptables-restore < logs/iptables-before-cleanup.rules`.

## Как добавить свой сервис

Скопируй любой шаблонный модуль и замени три вещи: список доменов, цепочку, порты.

```c
static const char *const site_domains[] = { "mysite.com", NULL };

#define SITE_MODULE_PREFIX   mysite
#define SITE_MODULE_CONFIG   mysite_config_t
#define SITE_MODULE_CTX      mysite_ctx_t
#define SITE_MODULE_CHAIN    MYSITE_BYPASS
#define SITE_DNS_PORT        18580
#define SITE_RELAY_PORT      18480
#define SITE_MARK            0x4d5a
#define SITE_LABEL           "MYSITE"
#include "src/common/site_module_impl.h"
```

Порты не должны совпадать с уже занятыми. Занятые DNS-порты:
`18556, 18558, 18562–18568, 18590`; релей — `18445` у google, `18444` у discord,
`18444` и `15353` у vrchat, `1443` у telegram.

**Про метки — честно.** Правило исключения собственного трафика одно на проект:
`-m mark --mark 0x4d50/0xfff0 -j RETURN`, то есть пропускает пакеты с меткой
`0x4d50`–`0x4d5f`. У большинства существующих модулей метки стоят выше — в
`0x4d66`–`0x4d72`, то есть **вне** этого диапазона. На живом трафике это не
проявляется, и вот почему: рель подключается к адресу CDN, а правила модуля
нацелены на закреплённые адреса того же CDN, поэтому пакеты реле в собственные
правила не попадают. Метка — страховка на случай, если адреса совпадут. Новому
модулю лучше брать `0x4d50`–`0x4d5f`; если тянет на свои — знай, что страховка
на него не распространяется.

Дальше две строки в `Makefile` — в `MODULES` и вызов `PLUGIN_template` — и `make plugs`.

Подробности API: `src/common/site_bypass.h`, `src/plugin_api.h`.
